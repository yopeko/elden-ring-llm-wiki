# 簡報規劃（步驟二：先討論、後生成）

## 簡報定位
- **題目**：艾爾登法環世界觀入門——法環、黃金樹與破碎戰爭
- **對象**：沒玩過、或玩過但沒研究劇情的人
- **學習目標**（看完能回答）：
  1. 艾爾登法環、黃金樹、黃金律法分別是什麼？
  2. 誰在統治交界地？（權力金字塔：無上意志 → 瑪莉卡 → 半神 → …）
  3. 世界為什麼會壞掉？（黑刀陰謀之夜 → 法環破碎 → 破碎戰爭）
  4. 玩家（褪色者）是誰、要做什麼、結局有哪些選擇？
  5. 這些說法哪些是遊戲文本、哪些是考據解讀？

## 簡報產生的 graph（規劃當時的版本）

> 註：實際執行時，「產生 HTML」被拆成獨立節點 ⑤、瀏覽器實測改為 ⑥，內容檢查也從 S1–S4 增加到 S1–S5。最終版本請看 `report/流程說明.md`。

```
① 規劃大綱 ──（使用者確認）──→ ② 查 Wiki，建立「投影片 ↔ Wiki」對照表
                                      │
                                      ▼
                         ②' 對照表檢查（前移的檢查）
                         每個論點都要有 Wiki 頁＋標籤；〔推測〕要明示
                                      │ 通過         ╲ 不通過 → 回 ②（補查 Wiki）
                                      ▼                          或回 Wiki ingest（Wiki 沒有）
                         ③ 依對照表撰寫 HTML
                                      │
                                      ▼
                         ④ 內容檢查（tools/check_slides.py）
                           S1 每張有來源頁、來源頁存在
                           S2 投影片文字 vs 來源 Wiki 頁的用字重疊（L9 的簡報版）
                           S3 術語先定義後使用（新手可讀性）
                           S4 學習目標 1–5 都有對應投影片
                                      │ 通過         ╲ 不通過 → 回 ③（改寫）或 ②（換來源）
                                      ▼
                         ⑤ 瀏覽器實測（內建瀏覽器）
                           翻頁、主控台錯誤、手機寬度、深淺色
                                      │ 通過         ╲ 不通過 → 回 ③（改 HTML／CSS）
                                      ▼
                                   完成並發佈
```

**設計理由**：Wiki 階段的教訓是「錯誤最常出在生成，而且是 LLM 自己的話混進來」。所以這次把檢查**提前到撰寫之前**（②' 對照表）：先確定每個論點出自哪一頁 Wiki，才開始寫；寫完再用 S2 比對一次。

## 呈現方式
- 單一 HTML 檔，不依賴外部函式庫；左右鍵／點擊翻頁，有進度條。
- 每張投影片底部顯示「📚 來源：wiki/…」，〔考據〕〔推測〕用不同顏色的小標籤標在句子旁邊。
- 視覺：暗色背景＋金色（呼應黃金樹），延續你 RAG 作業的暗金風格。
